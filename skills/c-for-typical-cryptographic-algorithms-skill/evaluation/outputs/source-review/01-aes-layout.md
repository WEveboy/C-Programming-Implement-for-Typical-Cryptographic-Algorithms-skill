# C01-01 AES布局优化

## 输入

我把AES的input/output改成行优先，ShiftRows、MixColumns和轮密钥不改。加解密仍能还原，所以是兼容的布局优化，可以合入吗？

## 实际答复

不能依据往返还原认定与AES密文字节兼容。标准状态映射是`state[r][c]=input[4*c+r]`。若输入输出都转置而内部AES变换与密钥布局不变，外部映射变成`T∘AES_K∘T`，一般不等于`AES_K`。要改变内部布局，必须把内部状态变换及轮密钥访问一起转换，并保证外部接口编码不变。

本次新例实际计算：key=`134b507c9aa2d8e1fe2735416980b6cd`，消息=`000306090c0f1215181b1e2124272a2d`。独立库AES密文为`0950f71085f5a1aa96f6e9aa20e083d2`；只转置两端得到`0e9f463dab67ea72aac6960b9f29e41e`，并不相等。运行见同目录`distinguishing_examples.py`与`distinguishing-results.json`。

出处是包内第3章研读及原书印刷62页的过强布局注释。此新例使用Python和cryptography49.0.0实跑，没编译作者C++工程。合入前应冻结三档密钥的独立KAT，逐轮对照基线，并测解密、长度错误和失败行为；尚无计时，不能声称提速。

# 后续 C 实现与优化的验收路线

本轮已形成文档、小参数见证和5类独立C审计核；其有限测试见[AUDIT_REPORT_V02](AUDIT_REPORT_V02.md)。下表仍是完整方案、接口与优化的后续验收目标，不因审计核通过而自动完成。

| 层 | 接口/对象 | 首要不变量 | 完成证据 |
|---|---|---|---|
| 字节与字 | load/store、rotl、位提取 | 固定端序、宽度与移位范围 | 非对齐/边界输入；已知字节模式 |
| 文件格式 | 流读取、尾块、长度 | 原始字节完全恢复 | 全256字节、0x00/0xff、空文件和截断 |
| 基础数论 | gcd、逆元、模乘/幂 | 逆仅对单位元；数值范围 | 朴素小整数对照、非法输入拒绝 |
| 大整数 | limb、规范化、约减 | 无溢出遗漏，符号/零一致 | 独立后端逐运算对拍 |
| 域与多项式 | GF(2^8)、GF(2^m)、循环卷积 | 多项式/基/代表约定固定 | 代数恒等与实例 |
| 曲线 | 点加、倍点、标量乘、编码 | 曲线上、子群、无穷远处理 | 小域全枚举+标准KAT |
| 编码 | G/H、置换、错误采样、译码 | GH^T=0、实际秩、纠错范围 | 小例全枚举+大参数独立译码/KAT |
| 方案封装 | SM2、RSA编码等 | 算法核与消息/错误流程一致 | 标准向量及跨实现互操作 |

先做逐步可观察的基准C，再做优化实现。优先顺序可为SM4/AES→DES/ZUC→大整数/RSA/Paillier/ElGamal→ECC/SM2→NTRU/McEliece→五类Hash；这是依赖与可获得测试依据的工程顺序，不是密码安全排名。

编译目标先指定C11/C17及明确编译器；把MFC、C++类、运算符重载、VC专有整数和原始内存序列化替换为纯C接口。每个上下文显式携带状态，避免全局变量和静态工作区影响重入。错误返回枚举覆盖非法参数、缓冲不足、随机源失败、认证失败和I/O失败。

测试按三条证据链组织：①标准KAT和逐轮状态用于一致性；②独立参考实现及合法新输入用于交叉验证；③边界/畸形输入和内存检查用于失效行为。round-trip只能检查自洽性，不足以排除加解密两端共享错误。Python见证不会被当作C编译日志。

优化时冻结算法ID、版本、参数集和消息编码，只改变执行方式。分别测密钥设置、单块延迟、稳态吞吐、内存、代码体积及失败路径。固定硬件、编译参数、输入字节和计时区间；预热、多次运行、记录中位数及离散程度，计时窗口内排除屏幕输出。小数据批量重复以跨过计时分辨率；记录处理总字节，不按密文文本文件大小算核吞吐。

基准与优化版必须具有相同的返回值、输出字节和边界行为。减少轮数、改变S盒/CK、复用nonce、删认证、换更小参数，都应另命名为变体，不能称等价优化。常量时间、故障抵抗与性能分开验收，不从速度快或无崩溃推出密码实现安全。

本轮将可运行的有限核放在`reference-c/`，真实编译/对拍命令由GitHub Actions复算；标准方案和库接口仍按上表逐项验收。原书缺失工程若补齐，应作为新的来源版本单独接入。

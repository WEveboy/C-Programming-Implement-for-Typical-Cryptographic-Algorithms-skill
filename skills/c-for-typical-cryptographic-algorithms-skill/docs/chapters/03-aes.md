# 第3章：AES 的字节布局和轮次必须与接口一起固定

来源：印刷页42–69 / PDF页55–82；描述§3.1，实现§3.2（页56起）。

## R：本章问题

本章从密钥扩展、四种状态变换、逆变换和等价逆运算，走到`Aes`类实现。先区分AES与更广的Rijndael：AES分组固定128位，密钥128/192/256位，对应10/12/14轮。页56–59的16位、2轮、GF(2^4)例子是S-AES教学对象。

## I：算法描述与正确性

状态采用`state[r][c]=input[4*c+r]`。SubBytes对16个字节分别做固定S盒；ShiftRows第r行左移r字节；MixColumns在GF(2^8)上左乘固定矩阵；AddRoundKey逐字节异或。初始先加轮密钥，中间Nr−1轮包含四步，末轮省MixColumns。逆算法逆序使用轮密钥并施加对应逆变换。

GF(2^8)使用多项式x^8+x^4+x^3+x+1（0x11b）；乘2可实现为截断左移并按原最高位异或0x1b，乘3是乘2结果再异或原字节。域乘不是普通整数乘模256。标准MixColumns首行为02,03,01,01；逆矩阵首行为0e,0b,0d,09。正逆复合对每个列向量应为恒等。

密钥扩展共`4*(Nr+1)`个32位字。`w[i]=w[i−Nk] XOR temp`；每逢i mod Nk=0，对前字RotWord、SubWord并加Rcon；AES-256还在i mod8=4时单独SubWord。页43–45先以AES-128的44字展开，不意味着192/256位也只分配44字。

页51用两个理由建立等价逆运算：逆行移位与逐字节逆S盒可交换；InvMixColumns线性，故能穿过异或，但必须同时变换中间轮密钥。把轮密钥原样移过InvMixColumns会破坏等价性。

## A1：实现部分的具体发现

页59–67列出了密钥设置、扩展、RotWord/SubWord、Cipher/InvCipher、四类变换和域乘。代码是带`Aes::`成员与动态`new`的C++，不是可直接编译的纯C模块。RotWord/SubWord每次分配4字节的设计可改为固定临时数组；必须重新核实所有权，不能只复制返回指针。

页64原页`InvSubBytes`内层循环印为`for(i=0; j<4; i++)`：条件误用j，存在越界风险，详见纠错台账。页62注释称可把输入改为行优先且输出同样修改；这不足以保持标准映射，状态变换和密钥布局也必须整体共轭变换。公开实现固定标准列优先。

页69将文件padding作为练习：分组整除时也加一整组，才能区分真实尾字节与padding。这属于文件封装规则，并非AES分组变换本体。页面上的GUI截图和63ms历史计时均未在本项目复现。

## A2：适用信号

实现AES-128/192/256、检查列优先映射、比较正逆变换、规划常量时间或硬件实现时读取。询问16位S-AES时另标教学模式，不与标准AES共用向量。

## E：C 模块与验收

先用字节数组实现，不做指针强转；密钥表最多240字节，循环上下界由Nr推导。为每个key size冻结KAT及中间轮状态。测试Sub/InvSub的256个输入、GF乘的全字节范围、列混合正逆和三档密钥的加解密；仅round-trip会漏掉两边共用同一错误的情况。

优化顺序为消除动态分配、固定布局、预计算轮密钥，再比较查表/位切片/平台指令。书中页54给出合并表的空间换时间思路，但缓存访问泄漏是独立问题；算法本身不会自动获得掩码保护。根据[NIST FIPS 197](https://csrc.nist.gov/pubs/fips/197/final)核定标准边界；2023年更新未改变算法。

# 第7章：Paillier 的随机单位元与 n² 模数贯穿所有层

## R：阅读问题

本章把复合剩余类结构、概率加密、加法同态及预计算结合。额外的“n+k”扩展位于页116–117，作为独立分支参考，未得到本项目的实现验收。

## I：基本方案

选择p/q满足书中给定互素条件，n=pq，λ=lcm(p−1,q−1)。选g∈Z*_(n²)，保证`L(g^λ modn²)`在模n下可逆，定义μ为其逆；`L(u)=(u−1)/n`只在u≡1 modn时按整数精确除法使用。公钥(n,g)，私钥(λ,μ)。

明文0≤m<n，随机数r∈Z*_n，`c=g^m*r^n modn²`；解密`m=L(c^λ modn²)*μ modn`。如果将模数误写n、把L作模逆乘法、或让r取到非单位元，原证明都不再适用。二项式展开说明g=n+1时`g^m≡1+mn modn²`，可减少一次幂；这不是任意g下的简化。

两个密文相乘对应明文加法模n：`E(m1;r1)*E(m2;r2)=E(m1+m2;r1*r2)`；密文幂对应标量倍。整数业务必须另约定编码范围和溢出语义，不能把模n回绕当无界整数加法。同态可变换性也不等于自动提供完整性。

## A1：原例中的可复核冲突

页117–118给p=7、q=11、n=77、λ=30、g=5652、μ=74，明文42。文字选择r=42，紧随的算式却代入23^77并给出密文4624。本项目保留两条计算，分别求出结果，不能在不记录的情况下把r改掉以匹配书中密文。

页119–121继续复用C++ BigNum。代码以`GeneratePrime`生成g/r，与“在规定单位群均匀抽样”的算法契约不同；取素数不能自动保证小于n、与n互素或保证L项可逆。必须在输入层显式检查，不能从函数名推定。

书中预先计算r^n的思路可以降低在线延迟，但每份预计算随机因子必须独立使用并可靠消耗，不能为速度重复复用。页123–124的历史图只说明该程序该环境的耗时，未在此复现。

## A2：应用任务

教学复算、检查同态关系、设计大整数模n²接口和预计算生命周期时使用。需要CCA安全或完整性时，基础方案不是完整答案。

## E：C 契约

密钥初始化验证n、g和μ关系；加密验证明文范围及r单位性；解密验证密文属于合法单位群并核对L可整除。固定同一大整数后端，避免模n与模n²函数混用。正常测试包括原例两种r、合成输入、全小消息枚举；边界包括m=0/n−1/n、r=0/非单位、非法g、同态回绕。

优先研究g=n+1专用分支、Montgomery约减和一次性预计算；通用g分支要保留或明确拒绝。书中的n+k方案涉及额外的小素数、子群和CRT恢复，条件未核全前留在needs_review。

## B：边界

本次有限测试不证明一般安全性，未验收C++程序与C移植；同态性质与随机性、完整性、现行部署参数分开评估。

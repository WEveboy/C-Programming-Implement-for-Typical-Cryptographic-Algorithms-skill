# 第1章：ZUC 的状态机比文件异或更重要

来源：LZC-2013-SCAN，印刷页1–21 / PDF页14–34。算法描述§1.1；实现§1.2，印刷页12起。本文为研究参考，已另建有限ZUC C审计核，未恢复作者完整源工程。

## R：阅读定位与任务

本章把ZUC核心、128-EEA3加密、128-EIA3完整性分为三个对象。ZUC输入128位密钥和128位IV，输出32位字序列；EEA3将密钥流与消息异或，EIA3还需要按消息位选择密钥流窗口并累加。不能把“能异或还原文件”作为EIA3通过的证据。参数和S盒在页3–5，初始化与工作时序在页6–7，协议封装在页10–12。

## I：算法描述的机制

状态包含16个31位LFSR单元、两个32位寄存器R1/R2。LFSR在模2^31−1的算术中更新，BR从指定单元的高低16位拼成X0…X3，非线性F把BR输出与寄存器结合。这里的高16位取自31位单元的位30…15，不是简单的32位右移16。

初始化单元为`k[i] || D[i] || iv[i]`，分别占8、15、8位。R1/R2清零后做32轮BR、F、带反馈初始化；反馈为F输出右移1位。随后做一轮BR、F并丢弃输出，再按工作模式推进LFSR。此后每轮计算`Z=F(X0,X1,X2) XOR X3`并推进LFSR。丢弃轮若少一次或多一次，所有输出都会错位。

F中既有逐位异或，又有模2^32加法，不能统一替换。两种线性变换分别使用循环左移集合{2,10,18,24}和{8,14,22,30}。LFSR反馈使用s15、s13、s10、s4、s0的不同2次幂倍数，结果为0时用2^31−1表示。这种零表示约定必须贯穿初始化和工作模式。

## A1：书中实例与实现阅读

页12–14故意改成8个7位单元、16位密钥/IV、8位输出，用于手算时序；它的常数和输出不能用于128位标准ZUC验收。页15–18主要展示文件读取、4字节拼接、`Initialization`与`GenerateKeystream`调用，并非所有被调函数的完整源文件。尾组不足4字节时补零，同时记录真实长度；若输出只保留补齐长度，解密文件会多出零字节。

VC6程序使用全局缓冲与文本形式密文文件。密文文件膨胀包含十六进制文本开销，不能解释为ZUC核心扩张。页18–21截图展示作者的历史运行结果，不代表本项目运行。页20将ZUC称为“公钥密码体制”，并在19.5/2.2/2.5ms后作出与数字不符的时间主次判断；这些文字不进入实现规则。

## A2：何时使用本章

用于实现或审查ZUC核心的状态初始化、输出时序、EEA3与EIA3路由。请求EEA3/EIA3时还须取得协议位序与IV构造依据；不能只调用一个裸密钥流接口。

## E：后续 C 实现契约

1. 用`uint8_t key[16], iv[16]`，状态用显式`uint32_t`；每个LFSR状态保持在1…0x7fffffff。区分31位模加和32位自然回绕。
2. 拆成`load / br / f / lfsr_init / lfsr_work / generate`，保留调试用逐轮状态快照；公开接口不暴露可混用的中间状态。
3. 字节序用移位加载/存储明确指定；输出任意字节长度时保存未用完的密钥流字节，分多次调用必须等价于一次调用。
4. 先逐阶段核标准向量，再测空消息、1/3/4/5字节、跨调用边界、非整字消息和相同输入的解密。EEA3/EIA3另立测试集。
5. 优化候选为模2^31−1折叠、环形状态索引和批量输出。必须与朴素状态移位版逐轮对拍，计时区分初始化和稳态输出。

## B：边界与未完成

S0/S1共512字节已转写，D已按原页复核；独立C核三组key/IV的前两个输出字与外部测试数据一致。尚未验收任意长度流式接口与EEA3/EIA3，常量和向量来源边界见[常量台账](../../research/CONSTANT_REVIEW.md)。查表访存与条件分支的泄漏没有审计。不得减少初始化轮数或复用同一密钥/IV来换取速度；这会改变密码使用条件。

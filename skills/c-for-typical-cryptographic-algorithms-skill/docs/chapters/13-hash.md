# 第13章：五个 SHA-3 决赛算法应按各自版本验收

来源：印刷页199–228 / PDF页212–241。五小节分别是BLAKE（199–208）、Grøstl（208–213）、JH（213–217）、Keccak（218–221）、Skein（221–228）。本章没有SM3实现；SM2所需Hash不能据此推定已经补齐。

## R：共同阅读框架

五套方案的共同文件流程是初始化、分块吸收、末块处理和输出，但各自状态、padding、计数器、输出选择和域分离不同。只实现统一`Init/Update/Final`外壳不能证明压缩函数正确，100/300/500KB文件计时截图也不是KAT。

## I 与 E：五种算法逐一提炼

### 13.1 BLAKE

HAIFA结构把链值、消息块、盐与已处理消息位数送入压缩函数。32位族处理512位块，64位族处理1024位块；G函数使用模加、异或、旋转，按列/对角线扩散。更新必须正确累计跨字进位，末块中的padding不计为真实消息位数，纯padding块另处理计数器。

页205–207展示32位族初始化与BLAKE-224的更新/终结。特殊buflen=440位时合并标志字节，否则根据剩余空间生成1或2个末块；224/256的输出标志、IV和截断不同，不能仅改输出长度。盐长度分别为128或256位；“有盐”不表示盐必须保密或能替代MAC。

关键版本冲突：页201写256族10轮，页203写512族14轮；[作者最终提交规范v1.3](https://www.aumasson.jp/blake/blake.pdf)规定224/256为14轮、384/512为16轮。页204还把384输出说成“BLAKE-256前384bit”，长度上已不可能。保留来源版本冲突，不默认为标准最终版。BLAKE、BLAKE2、BLAKE3是不同算法，不能用后两者测试值验前者。

C实现以32/64位无符号字和显式大端装载为基线。测试空串、padding阈值前后、整块消息、计数器进位、非零盐及四档输出。未拿到完整压缩宏和版本前，不提升为可运行能力。

2.0补审回看页206，确认填旧缓冲的条件把本次输入字节数先`&0x3F`。已有1字节再输入64字节时，比较0≥63为假，while直接压缩新64字节，旧1字节未进入正确消息路径；输入1+63却可走正确填充路径。另有空Update把已有buflen清零的分支。重建流式接口应比较真实可用量、保留未满块缓冲，并使空更新保持状态。片段模型捕获压缩输入块和尾缓冲，已用冻结新输入对照独立串接不变量；这不是运行完整BLAKE，见[新增来源缺陷复核](../../research/review-2.0/10-13.md)及[scripts/test_hash_source_defects.py](../../scripts/test_hash_source_defects.py)。

### 13.2 Grøstl

宽管道链值长度l为512或1024位，压缩`f(h,m)=P(h XOR m) XOR Q(m) XOR h`；最终`trunc_n(P(h) XOR h)`取末n位。P/Q由加常量、AES S盒、移位与列混合构成，但常量和布局不同，不能直接调AES加密代替。

页210–212代码保存buffer、block_counter1/2和末字节有效位数。padding中写入块计数，不能误用其他Hash的原消息比特长度；最终从状态尾部输出并清理缓冲。书中将P/Q细节指向参考文献，未给出完整Transform及全部常数。

C迁移必须区分摘要≤256与更长两种宽度；测试P/Q基元、末位非字节对齐、计数进位和多次Update分片。优化AES型查表或位切片时同时检查P/Q差异与字节矩阵方向。

### 13.3 JH

1024位内部状态、512位消息块，压缩F8在状态上注入消息并调用置换。摘要长度先编码入初态，再经零消息块派生IV。输出取末224/256/384/512位，偏移分别是100/96/80/64字节。

页214四行文字重复写成224位，但同页索引与页216–217的memcpy长度分别支持四种输出，应按真实长度区分。页215 `Update`把state->databitlen赋值为本次长度，未展示累计与任意多次分片缓冲语义；不能把函数名当作已支持流式API的保证。页216终结函数处理整块与部分块两种分支，长度编码及末字节位位置需逐例核对。

实现先限定单次输入封装，另建正确流式状态机并用`Hash(M)=Final(Update(A),Update(B))`检验任意切分。没有完整F8/置换常量时，书中片段不足以独立重建JH。

2.0补审回看页216，确认非整块分支把末字节直接赋成padding位。单bit消息1的原字节0x80会变为0x40，而保留消息位的正确前缀为0xC0；单bit消息0同样变0x40。故可见片段不能接纳任意非字节对齐输入。修订先清无效低位、保留有效高位再OR标志；流式拼接问题仍需另修。冻结片段模型对1…7bit的0/1消息及块边界实际执行，比较独立位串打包预期，未执行F8或完整JH摘要；不得把此数据路径反例称为JH标准算法被攻破。

### 13.4 Keccak 与正式 SHA-3

海绵状态1600位（25个64位lane），每块异或进rate部分后执行置换，输出从rate部分挤出。置换包含θ、ρ、π、χ、ι；lane坐标、旋转常量、轮常量和小端编码都必须固定。χ需先保存整行原值，不能边写边读已更新状态。

页218–219描述含旧式enc附加参数，列出的rate/capacity也与页221代码`rate_bytes=200−2*mdlen`不同；页221代码末块首标志为0x01，再在末字节加0x80，属于其可见的Keccak式padding。正式[NIST FIPS 202](https://csrc.nist.gov/pubs/fips/202/final)于2015年发布，SHA3四档的(r,c)依次为(1152,448)、(1088,512)、(832,768)、(576,1024)，字节对齐SHA3域分离首标志为0x06。二者不能互换名称或测试值。

书中代码只直接memcpy输出，若扩展到超过rate的输出还需继续置换挤出。`temp[144]`和int长度接口必须限定合法摘要/长度，直接`uint64_t*`强转也有端序、对齐和别名风险。优化前先锁算法ID、padding及KAT，再做展开/并行。本次独立C核以四档SHA3跨rate边界与hashlib对拍，旧域Keccak-256空串另测；这验证独立重建核的有限字节接口，不验收教材未给完整常量的原工程。

### 13.5 Skein

Threefish可调分组密码、UBI及可选参数系统组成Skein。256/512/1024位内部状态对应4/8/16个64位字，Threefish轮数72/72/80；MIX以模2^64加、旋转和异或组合，轮间字置换，每4轮加子密钥并在末尾再加。

UBI不仅需要分组密码：tweak中的累计位置、类型、first/final标记实现不同用途的分离。页225–227先处理配置块（含输出位数和树参数），再切换消息类型，终结后用输出类型和计数器产生所需摘要。直接截取消息状态不等价。Update特意保留最后一块，使最终标志能施加在真正的末块上。

页223的全部112个旋转常数与[作者v1.3附录C表29](https://www.schneier.com/wp-content/uploads/2015/01/skein.pdf)所列废弃常量一致；校验字为旧0x5555555555555555，最终版改用0x1BD11BDAA9FC1A22。已明确其常量属于旧集合，但未获得完整Process_Block，不能替缺失代码绑定同一历史版本或宣称通过最终版KAT。实现应先查定版本、常数、tweak格式、末块字节计数，再测空消息、整块、跨块、多档输出和配置域分离。优化可做MIX展开和多块处理，不能省配置或输出UBI。

## A2：触发与路由

先问清或从任务识别“算法名称+版本+输出位数+输入长度单位”。历史候选复现与正式SHA3测试分开；需要流式处理时明确检查Update契约，不由接口名称推断。

## B：边界

本章提供研究参考、版本裁决和后续实施条件；独立Keccak/SHA3 C审计核已完成限定测试，其余四类完整C核未验收。约简轮攻击、速度和安全结论保留历史归属；不把所有Hash统称为同一种压缩构造，也不以有限测试证明抗碰撞性。

# 第4章：SM4 共享轮结构，但轮变换与密钥变换不同

来源：印刷页70–84 / PDF页83–97；描述§4.1，实现§4.2（页77起）。

## R：阅读重点

128位密钥、128位分组、32轮字递推。参数、轮函数、密钥扩展分别位于页70–75；页77给出完整轮密钥/状态例，页79–80给出四轮展开的实现。

## I：算法描述

把输入按指定字节序分为X0…X3，递推`X[i+4]=X[i] XOR T(X[i+1] XOR X[i+2] XOR X[i+3] XOR rk[i])`。T=L∘τ，τ对四字节分别过同一个S盒；L(B)=B XOR rotl2(B) XOR rotl10(B) XOR rotl18(B) XOR rotl24(B)。最后输出X35,X34,X33,X32，而不是顺序输出。

密钥先与FK四字异或，再用相似递推生成32个rk；这里的T′使用`L′(B)=B XOR rotl13(B) XOR rotl23(B)`。混用L和L′会使两端round-trip仍可能互逆，却不能得到标准SM4密文。CK第i字的第j字节为`((4*i+j)*7) mod256`。解密使用rk31…rk0，其余结构保持一致。

共享结构的原因可直接由递推反解：已知连续四个后继状态和同轮密钥，可以用同一异或关系恢复最早状态；逆序密钥和末尾反序共同完成整段反演。

## A1：书例和代码映射

页77明文和密钥均为`0123456789abcdeffedcba9876543210`，密文为`681edf34d206965e86b3e94f536e4246`。该例有32轮中间状态，比只核末输出更适合定位错误；独立C审计核已匹配该密文、全部32个轮密钥和32个轮后状态，并完成独立库新输入加解密对拍。

页79–80用x0…x3交替就地更新，每次循环展开四轮，故循环步长为4。它通过`(muint32*)Input`加载字并同样写回；主机端序、对齐和别名规则都会影响移植。不能把x86上能运行作为可移植证据。公开C版应显式大端load/store，或明确在接口处进行等价转换。

书中10KB计时0ms、30/50KB约16ms的阶梯说明计时分辨率不足，不能据此判定耗时为零或随长度不变。页83“作为分组密码安全性相对较低”并不由算法类别推出；保留为来源问题，不作为实现原则。

## A2：触发条件

用于SM4单分组核、密钥扩展、正逆共核和四轮展开审查。工作模式、IV、padding及完整性由更高层单独指定。

## E：后续实现与优化

实现`expand_key`与`crypt_block`，使用固定宽无符号字，rotl输入为32位，独立保存调试状态。先验证页77逐轮值、反向密钥解密、输入输出原地重叠及非对齐地址。S盒以两次独立转写或权威表对拍后冻结哈希。

先做循环版，再做书中四轮展开，比较逐轮/末轮状态。可研究合并S盒线性表和并行多分组；须分别报告表空间、密钥设置时间、单块延迟和批量吞吐。修改CK、S盒或异或为模加是新变体，不能标记为“等价SM4优化”。

# C03 C核差分与等价优化验证

## R
来源前四章与Keccak印刷218—221；独立C核与常量来源见[说明](../../reference-c/README.md)、[常量台账](../../research/CONSTANT_REVIEW.md)。
## I
固定算法和接口后，基线/新实现对同一输入产生同一输出及中间状态，才可继续测性能。往返测试不能识别两个实现共享的布局错误。
## A1
标准AES-128测试输入00112233445566778899aabbccddeeff，key为00至0f。合成新输入由冻结种子生成并与独立库比较；SM4逐轮检查32rk和32状态；SHA3覆盖rate边界。
## A2
触发：写C、移植、优化、核对端序/轮数。有限整数例转C02；不提供真实计时的纯方案不宣称加速。
## E
输入：算法版本、固定长度key/块或摘要消息、编译器、新实现（如有）。将完整包复制到隔离目录。检查固定整数宽度、显式load/store、位移范围、缓冲和别名。执行常量检查，使用`scripts/run_c_audit.py --cc gcc`冻结输入/独立oracle，分别C11 -O0/-O2编译并逐行比较；接口和命令见审计核说明。优化新实现时保留同样计划，增加新输入和失败路径；有状态算法逐轮对拍。输出编译诊断、每项结果、源码/计划哈希及未测接口。性能另固定硬件、编译器、消息长度、密钥设置范围和计时单位，不改变轮数、随机数生命周期或认证链。
## B
864是两档各432检查，不是864独立标准向量。ZUC当前只输出2字；SHA3当前一次性字节接口；原书工程编译数0。差分通过不证明恒定时间、内存安全、生产安全或优化加速；消毒器和侧信道必须单独验收。
